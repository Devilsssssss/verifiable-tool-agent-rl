# Verifiable Tool-Agent RL

## 5 分钟版本

这是一个研究“工具调用模型是否真的遵守业务策略”的可复核项目。模型在带 SQLite 状态的本地零售环境中完成取消、拒收升级、换货、期限内退货和过期退货等任务；成功不由文本相似度决定，而由数据库终态、工具调用顺序、目标订单检查和业务政策共同评分。

## 我做了什么

- 设计 10 个工具、5 个业务族和严格的 `strict-v2-target-inspection` 评分协议；
- 生成 300/60/120 的训练、验证和冻结确认任务，完成专家轨迹重放、实体隔离、隐藏 ID 捷径和真实 SFT mask 审计；
- 通过诊断定位首步邮箱字段污染和“总选列表第一项”的订单位置捷径；
- 用等预算位置平衡 SFT 和退货边界监督对照验证假设，做 seed45/46/47 复验、holdout、旧确认集回归和 task-level gained/lost 分析；
- 保留负结果：收益依赖训练 seed，目标订单检查和位置 2 仍未过门槛。按冻结协议完成的双 seed GRPO 没有超过匹配 SFT，因此没有把训练过程包装成 RL 增益，并停止继续调参。
- 当前唯一后续是 reason-code-v1 的同预算双 seed SFT 修复：它已完成数据和契约审计，但尚未完成服务器训练，不能提前写成模型增益。

## 主要结果

v8 的 60/120 成功全部来自目标订单第一位，暴露了位置捷径。位置平衡 v10 在旧确认集达到 105/120，seed46/47 均为 101/120，但未通过预注册的目标检查稳定性门槛。针对退货边界的 return-boundary-v1 在新 holdout 上为 seed45 `78/120`、seed46 `98/120`，旧确认集为 `87/120`、`103/120`；一个 seed 明显回归，另一个只是不确定的小幅变化。

## 可信边界与角色

这些结果支持“可验证环境和数据诊断能暴露模型策略捷径”，不支持“当前后训练流程已经带来稳定 RL 收益”。确认集曾参与开发分析，不能称为独立盲测；新 holdout 同时改变了实体、措辞和年龄分布，不能单独解释年龄的因果效应。

候选人角色覆盖环境与评分设计、数据生成、训练前审计、远端 QLoRA 编排、轨迹重放、配对统计和实验文档化。项目的亮点是把失败模式定位到可检验的策略条件，并设置进入 GRPO 的阻断门槛。
